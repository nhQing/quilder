# Form mẫu hệ thống — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Một component "Form" mẫu hệ thống (không xoá/sửa, chỉ nhân bản), và mọi thứ của form — ô nhập, URL nhận, cách báo kết quả (kể cả hộp thoại tự thiết kế), style từng phần — chỉnh được ngay ở sidebar.

**Architecture:** Thêm cột `Preset.system` + seed idempotent; mở rộng params của Composite Form (`afterSubmit`, slot `success`/`error`, `endpointKey` rỗng = chưa chọn); thêm `style.parts` (style có kiểu cho phần con của Composite, selector khai trong registry) xuyên qua schema → op `setStyle.part` → compiler CSS → Inspector; khối Form và "Gửi tới" trong Inspector gọi op thường và API endpoint có sẵn.

**Tech Stack:** Next 15 App Router, Prisma/Postgres, Zod, Zustand (editor store), Vitest, Playwright (`pnpm e2e:up` / `pnpm e2e:test <spec>` / `pnpm e2e:down`).

**Spec:** `docs/superpowers/specs/2026-11-03-form-mau-design.md`

## Global Constraints

- Không publish; không đụng dữ liệu staging trong lúc làm (chỉ e2e stack local).
- Chữ trên giao diện: tiếng Việt, câu nói được lý do (theo giọng các docblock sẵn có).
- Form cũ chạy y như cũ: thiếu `afterSubmit` + có `successPanel` → `panel`; thiếu cả hai → `inline`; thiếu `endpointKey` → `newsletter`.
- Chỉ admin đặt URL nhận MỚI (sửa URL, tạo nơi nhận, tách URL riêng) — UI và API. Editor vẫn chọn được nơi nhận đã có.
- Mẫu hệ thống: DELETE / PATCH / ops (API + MCP `apply_component_ops`) → 409 với câu: `Mẫu hệ thống — nhân bản rồi sửa bản sao.`
- `customCss` vẫn thắng `style.parts` (layer `doc-custom` sau `doc`).
- Sidebar không bao giờ ghi params không qua `parseCompositeParams`-strict; lỗi hiện cạnh ô gây lỗi.
- Mẫu hệ thống không chứa gì riêng của MaiMoney (chữ trung tính, không URL).
- Kiểm trước khi xong: `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm docs:check`, e2e các spec đụng tới.

**Thứ tự chạy:** Task 3 → 4 → 1 → 2 → 5 → 6 → 7 → 8 → 9 (cây mẫu ở Task 1 cần `endpointKey: ''` của Task 3; Task 5 cần `style.parts` của Task 4).

## Review Focus

1. Form danh sách chờ hiện có (`waitlist-f`, `successPanel`, ~20 dòng customCss) — render và gửi y như trước. → Task 3 có test hồi quy params thật của nó; Task 4 test customCss vẫn thắng.
2. Xoá một node nằm trong slot `success`/`error` → id treo trong `slots`; renderer phải bỏ qua, không lỗi. → Task 3.
3. Một param sai do sidebar gửi (ô select không có lựa chọn, tên ô trùng) → bị từ chối, form không về mặc định. → Task 6.
4. Editor gọi thẳng `POST /api/settings/endpoints` → 403. → Task 7.
5. Bản sao mẫu mới chưa có nơi nhận → form tắt kèm lời nhắc trỏ về sidebar, không gửi đi đâu. → Task 3.
